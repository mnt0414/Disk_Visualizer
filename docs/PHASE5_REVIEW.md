# Phase 5 completion review

## 結論

Phase 5「アプリキャッシュ認識」は初期リリース範囲で完了とする。

完了の根拠は、固定パスを名前や日時だけで推測せず、版管理された定義とパス境界で分類し、根拠・信頼度・再生成可否・整理時影響をUIで確認できることにある。アプリ内削除は提供せず、「安全に削除できる」と断定しない。

## 完了条件

| 完了条件 | 結果 | 根拠 |
| --- | --- | --- |
| 名前や日時だけでキャッシュ認定しない | 達成 | OS、root、パス要素境界、定義ID・版で分類 |
| 「安全に削除できる」と断定しない | 達成 | 再生成時の影響と容量推定の限界を表示 |
| UIから定義バージョンと判定根拠を確認できる | 達成 | 保存済み分類queryとアプリキャッシュ詳細を実装 |
| 過去結果を新定義で読み替えない | 達成 | カタログ版・定義版一致時だけ現在の詳細を結合 |
| macOS／Windowsで検証する | 達成 | 通常CIの両OSテスト・デスクトップビルドが成功 |

## 初期カタログ

- Safari、Chrome、Edge、Firefox
- Adobe Media Cacheの既定`Media Cache Files`／`Media Cache`
- Blender Asset Library索引キャッシュ

Adobeは共有Media Cacheの検証済み既定パスだけを扱う。個別製品名だけで範囲を広げず、`Adobe/Common`全体も分類しない。

BlenderはAsset Library索引だけを扱い、物理シミュレーション、レンダー一時データ、自動保存、外部キャッシュを除外する。

## 実行時状態

初期リリースではOS固有の「使用中」断定を採用しない。スキャン中の2回の読み取り専用メタデータ観測により、`stable`、`changing`、`unknown`を保存する。`stable`は未使用を保証しない。

OS固有のロック・共有モード検査は、意味、偽陽性・偽陰性、権限失敗、通常アプリへの干渉を定義できるまで導入しない。この判断はPhase 5の未完了ではなく、安全な非採用判断として扱う。

## Phase 5から繰り越す項目

- DaVinci ResolveのCache／Proxy／Gallery設定読取
- Autodesk FlameのProject Home／Media Cache設定読取
- Adobeのユーザー指定Media Cache場所
- OS固有の使用中判定を将来導入する場合の仕様
- 実機でのAdobe／Blender分類スモークテスト

上記は固定パスを推測して追加しない。設定値を信頼できる方法で読み取れる段階で、別機能として設計・実装する。

## 次フェーズ

Phase 6ではFSEvents／USN Change Journal、履歴連続性、インデックス信頼状態、部分再スキャン、逐次キューを扱う。履歴欠落や対象の同一性不明を正常な差分結果として扱わない。
