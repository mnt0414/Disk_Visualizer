# SQLiteインデックス ベンチマーク

## 目的

Phase 3のストリーミング保存経路が、大規模なスキャンでも全件をメモリへ保持せず動作することを再現可能な方法で検証する。

## 実行方法

```bash
cargo test --manifest-path src-tauri/Cargo.toml benchmark_million_entries -- --ignored --nocapture
```

ベンチマークは次を実行する。

- 1,000,000件の疑似ファイル項目を生成
- 500件単位でSQLiteへトランザクション書き込み
- 完了後のレコード件数を検証
- 経過時間とDBファイルサイズを標準出力へ記録

通常のCIでは実行時間を安定させるため`ignored`とし、リリース候補やストレージ実装変更時に手動実行する。

## 合格条件

- SQLite内の項目数が1,000,000件と一致する
- 保留バッファが500件未満に保たれる
- セッションが正常完了するまで保存履歴へ表示されない
- `PRAGMA quick_check`が`ok`を返す
- 実行中のプロセスメモリがスキャン時ソフト上限750MBを超えない

## クラッシュ復旧

アプリ起動時に`in_progress`のまま残ったセッションは`interrupted`へ変更する。途中まで保存された項目は調査・将来の再開機能に備えて保持するが、正常な保存履歴としては表示しない。

完全な結果として扱えるのは`complete`セッションだけである。
